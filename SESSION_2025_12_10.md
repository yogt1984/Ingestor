# Session Notes - December 10, 2025

## Overview
This session focused on planning the v0.1 production roadmap for the Ingestor market making platform, with emphasis on CLI/TUI consistency and algorithm-agnostic design.

## Key Discussions

### 1. CLI/TUI Consistency Principle
**User's Key Statement**: "In development of the v0.1 everything that we can call via CLI should be callable via TUI ideally in this sense we should keep it consistent"

This became the guiding principle for the roadmap.

### 2. Terminology Clarification
The term "grid search" was identified as misleading:
- **Grid Search** = Parameter enumeration/tuning (NOT ML training)
- Current implementation hardcodes algorithm (A-S) and parameter ranges

**Proper Terminology**:
- **Tune**: Hyperparameter optimization (grid search, random search, Bayesian)
- **Train**: Model weight learning (for ML/NN algorithms)
- **Validate**: Cross-validation, walk-forward testing

### 3. Algorithm Categories Defined

| Category | Training | Examples | Degrees of Freedom |
|----------|----------|----------|-------------------|
| Rule-Based | None | Fixed Spread, Inventory Skew, Avellaneda-Stoikov | Parameters only |
| Statistical/ML | Supervised | Linear Model, Gradient Boosting | Weights + hyperparams |
| Neural | Gradient descent | MLP Predictor | Network weights |
| RL | Policy learning | PPO, SAC, DQN | Policy + value networks |

## Algorithm Parameter Definitions

### Avellaneda-Stoikov (as)
- Category: Rule-Based
- Trainable: No
- Parameters:
  - spread (bps): Base half-spread [default: 2.0, tunable]
  - skew: Inventory skew factor [default: 0.5, tunable]
  - max_inventory: Maximum position [default: 0.1]
  - quote_size: Order size [default: 0.001]
  - high_entropy: Threshold [default: 0.7, tunable]
  - low_entropy: Threshold [default: 0.4, tunable]

### ML Spread/Skew (ml)
- Category: Statistical/ML
- Trainable: Yes
- Parameters:
  - spread_intercept [default: 2.0, tunable]
  - spread_entropy_weight [default: -1.0, tunable]
  - spread_vol_weight [default: 400.0, tunable]
  - skew_intercept [default: 0.5, tunable]
  - skew_inventory_weight [default: -0.6, tunable]
  - max_inventory [default: 0.1]
  - quote_size [default: 0.001]

## Core Design Decisions

### 1. Algorithm Selection via CLI Flag
- Global `-a/--algorithm` flag applies to all subcommands
- Consistent with TUI where user will select algorithm first

### 2. Parameter System
- Algorithms self-describe their parameters
- Parameters marked as tunable vs fixed
- Enables dynamic UI generation

### 3. Trait Hierarchy (To Be Implemented)

